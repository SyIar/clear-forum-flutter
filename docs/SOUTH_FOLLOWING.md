# South 首页作者信息与本地关注

2026-09-29：最初按用户要求只改源码；用户随后明确要求打包，已包含在 [build 1027](BUILD_1027.md)。云端编译与自动检查通过，未使用模拟器，真机验收待用户进行。

## 首页展示

- South 的 Bookmarks / Recent reading：帖子标题下面展示发帖用户名，不再展示 `/read.php`；目录不再展示 `/thread.php` 等路径小字。原有楼层更新状态保留。
- `ForumEntry.authorName` 和 `ThreadPresentation.authorName` 单独保存作者名。作者主题页原有 `subtitle` 是板块与日期，不能将它误认为作者名。
- 作者信息来自目录行的主题作者或 thread 的 `#0` 楼，不用第 2 页第一个回复者冒充楼主。目录行头像和文字链接指向同一 UID 时取文字链接，不取最后回复者。
- 旧数据通过首页原有刷新补全：`trackedThreads` 本来就使用 thread root 请求，复用该响应，不额外逐个请求作者资料。暂时拿不到作者名就不展示路径占位，保留已知作者信息。
- South、Simp 首页顶部添加书签改为纯 `bookmark.badge.plus` 图标，保留 `Add bookmark` 无障碍标签与系统 toolbar 的原生玻璃效果。South 的黑名单入口也保持纯图标。

## 关注与 New

- 在 South 帖子里点作者头像，选择 `Follow author` / `Unfollow author`。
- 首页新增 `Following`。每个作者显示头像、用户名、最近 3 个主题；点作者打开完整主题列表，点主题打开原生阅读页，右侧取消关注图标可移除作者。
- 关注名单只保存在 South 的本地 `LibraryDocument`，不调用网站的关注接口。Simp 的本地库和 session 不受影响。
- 新关注时立即读取该 UID 的主题第一页；进入首页的首次刷新、下拉刷新与右下角刷新会同时检查关注作者。每个作者只请求一页，各作者按顺序读取；同一作者正在读取时复用请求，不抓取其全部历史。
- 依据用户此前提供的作者主题 HTML：`#u-contentmain .u-table` 的主题按发帖日期倒序，前 5 条日期为 2026-09-28、2026-09-28、2026-09-15、2026-09-11、2026-09-09。复用该列表顺序，按 thread ID 去重后保留前 3 条；排除侧栏链接及其他作者的数据。
- `New` 的含义是本 App 尚无该 thread 的成功阅读记录，不代表一定是今天发表。刷新、添加书签、加载作者主题列表都不会标记已读；成功打开帖子后去掉 `New`。帖子加载失败时仍保持未读。
- 使用 thread ID 识别阅读记录，兼容不同页码、作者过滤、URL query 写法与 fragment。只持久化轻量 ID，不持久化整页正文。
- 阅读标记独立于最近 10 条历史，历史淘汰或清空历史列表不会让已读帖子重新显示 `New`。
- 升级时复用已有 `recent` 与 `seenMaximum` 阅读证据；只有书签或 `latestMaximum` 不能证明读过。此前已被旧版本彻底清理的阅读记录无法还原，这类帖子首次可能显示 `New`。
- 拉黑作者会同时取消关注；取消拉黑不自动恢复关注。取消关注不清除已有阅读标记。

## 失败与持久化

- 用户不存在、登录失效、验证、网络问题或未知 HTML：保留上次成功的 3 条主题，展示简短错误与 Retry；有效的空主题列表才会清空旧主题。
- 取消关注后的在途响应不得重新创建关注。取消再关注产生新的 `followedAt`，旧响应不能覆盖新状态。
- 成功刷新只更新本地主题快照、作者信息、`checkedAt`，不改 `recent` 或阅读楼层基线。旧版库缺少新增字段时仍可正常读取。
- 每位作者的快照最多 3 条。只为书签、历史和当前关注快照保留展示元数据，旧主题元数据会被清理；已读 ID 保留用于未读判断。
