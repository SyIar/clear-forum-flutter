# Apple-native UI migration

Forum Lite no longer depends on ChunUI, Pika, or Pow. Earlier design-system notes
describe historical builds and are superseded by this migration.

## Implementation

- Use SF Symbols directly through SwiftUI Image, Label, Button, and UIKit UIImage.
  Symbol sizing uses system fonts instead of rasterizing SVGs into squares.
  Inline original-poster badges inherit a text baseline and remain solid blue.
- Use SwiftUI sheet and dismiss for presentation ownership, inherited environment,
  interactive dismissal, and item identity. Existing detents belong to each sheet.
- Use native alert, confirmationDialog, and UIAlertController. The small ForumUI
  target only adapts action models and shares the original-poster badge; it has
  no external dependency or assets.
- Use system button styles and semantic colors. ToolbarItemGroup owns spacing
  and the toolbar background, without another glass capsule nested inside it.
- Remove private blur filters, the global alert window, shader sweep animations,
  theme tokens, icon mapping, and the rule prohibiting SF Symbols.
- Show update activity with ProgressView and keep a stable navigation chevron
  after checking. Update details use a native resizable sheet.
- Keep download counts inside the native floating button. Floating reader controls
  share one material surface, and images have no decorative glass frame.
- Home uses Apple's glass button style; content actions use bordered styles.
  Original forum logos, wallpaper, reading preferences, and saved data remain.

## Verification

Run the native UI, Swift syntax, repository, and localization check scripts.
Syntax checking does not replace compilation. The macOS workflow runs existing
core tests and builds the device app. Packaging rejects retired UI resources and
checks the ProMotion opt-in.

Device acceptance should cover light/dark modes, large text, portrait/landscape
toolbars, native alerts and cancellation, sheet swipe dismissal and reopening,
page/chapter selection, update status, downloads, image/video viewing, and OP badges.
A CI build does not establish physical-device visual or interaction acceptance.

No Chinese runtime text or encoded Chinese literals are introduced. Localized
resources remain unchanged; no new LEO keys or configuration rollout is required.

## Apple references

- [Adopting Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass):
  prefer standard bars, sheets, and controls; remove interfering custom backgrounds.
- [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons):
  use standard controls and SF Symbols for recognizable actions.
- [Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets):
  keep sheet tasks focused and retain platform dismissal behavior.
